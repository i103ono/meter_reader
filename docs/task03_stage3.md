## 実装範囲

第9節の段階3として、固定レシピ、元ROIから独立した候補生成、
処理条件と画像の保存、同じ入力・設定からの再生成を実装した。
Planner・候補自動選択・人の確認処理・DB・Web・精度評価は対象外。

| レシピ | 順序 |
|---|---|
| resize_2x | Bicubic 2倍 |
| gamma_mild | 輝度Yを0.75乗 |
| clahe_mild | 輝度YのCLAHE |
| gamma_clahe | ガンマ → CLAHE |
| resize_gamma | ガンマ → 拡大 |
| resize_clahe | CLAHE → 拡大 |
| resize_gamma_clahe | ガンマ → CLAHE → 拡大 |

- 輝度はOpenCV.RGB2YCrCb.Y。ガンマは正規化後の0.75乗、8bit半端切上げ四捨五入。
  RGBの各チャネルに別々のガンマを掛けず、輝度処理のalphaはそのまま保持する。
- CLAHEのclipLimitは2.0。希望8×8タイルを、各辺floor(画素数/32)以下・最小1に制限する。
  32画素未満の辺は1タイル。パラメータは開発初期値で、精度保証ではない。
- 拡大はPillow BICUBIC、縦横とも2倍。6400万画素を超える出力は事前に拒否する。
  補間を、失われた数字・針の復元として扱わない。
- 合成レシピ内の処理は記載順に実行するが、別候補の画像を次の候補の入力にしない。
  すべてc0の未補正ROIから始める。元画像・元ROI・以前のrunは上書きしない。
- 未登録ID、同一IDの重複、3件以上の指定を処理開始前に拒否する。
  固定レシピ版はfixed-recipes-v1。任意コード、コマンド、保存された関数名は実行しない。

## 既存経路との接続

--recipes省略時は既存の段階1・2の動作を維持する。
指定時はstage=3となり、元ROIのc0、補正のc1/c2の画像・読取結果・試行情報を保存する。
元ROIを先に読み、補正候補は同じ質問・種別ヒントを使って独立して読む。
過去の候補値、前日の値、labels、evaluator、採用ポリシーはReaderへ渡さない。

最上位のreading/inferenceはc0の結果。候補ごとの結果はcandidatesに保存する。
自動選択はせず、selected_candidate_idはnull、effective_value/unitはnullのまま。
候補だけが読めた場合や候補に技術エラーがある場合も、自動採用へ進めずneeds_reviewにする。
元ROIのエラーや読取不能、候補のエラー、処理画像の生成件数は別々に残す。
失敗した候補へのReader呼出しは行わず、CLIの保存件数とエラー件数も分けて表示する。

2候補時の送信回数は未補正1回＋候補2回、それぞれ最大1回再試行なので最大6回。
VLMReaderは観測単位の期限を共有し、残り時間がなければ新しい補正や送信を始めない。
既存のバッチ金額予約は保持する。ソケットタイムアウトと前後の期限チェックを用いるため、
OSによる処理遅延やサーバー側課金のキャンセルまで保証する機構ではない。

## 記録と再生成

candidatesには親ID、レシピID、処理版、実際の処理順・パラメータ、
Python/OpenCV/NumPy/Pillow版・CPUアーキテクチャ、ファイルハッシュ、画素ハッシュ、
画像サイズ・モード、参考画質指標、Reader結果とAPI試行数を保存する。
画素ハッシュにはモード・幅・高さ・画素列を含める。
画質指標はYのp5/p50/p95・分布幅、暗部/飽和付近の割合、最大4×4領域の平均輝度差。
alpha付き画像の指標は白背景合成で計算し、画像自体のalphaは変更しない。
これらを信頼度・正解率・候補選択スコアとして使わない。

src/replay_corrections.pyは元のresult.jsonとrun内ROIだけを使い、モデルを初期化しない。
ROIのハッシュ、親ID、レシピ版、記録パラメータが登録処理と一致することを確認する。
画像参照は元run配下に限定し、パストラバーサルやrun外を指すsymlinkを拒否する。
再生成は別の一意なディレクトリへ排他保存し、元の読取結果を変更しない。
画素一致・PNGバイト一致・実行環境一致を分けて報告する。画素不一致は終了1。
ライブラリやプラットフォームが異なる場合の完全一致を推測で保証しない。
