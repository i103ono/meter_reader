# 計器読取・画像補正エージェント 要件・設計案 v0.2

作成日：2026-10-26（日本時間）  
更新日：2026-10-27（日本時間）  
状態：要件・設計のたたき台。Web確認・前日比較・CSV/Excel出力の要件を追加。実装・モデル選定・精度検証は未実施。

## 1. 確定した条件と提案する範囲

ユーザーが指定した条件は次のとおり。

| 項目 | 確定した条件 |
|---|---|
| 対象 | アナログ計器とデジタル計器の両方 |
| 外部サービス | 画像を外部AI APIへ送信できる |
| 主な画質劣化 | 計器が小さく写る・低解像度、暗さ・明るさのむら |
| Webでの確認 | 読取後に計器画像、目盛り、値、単位を確認できる |
| 履歴比較 | 同じ計器の前日との比較をWebで確認できる |
| 結果出力 | CSVおよびExcel（.xlsx）でダウンロードできる |

「メモリ」は計器の「目盛り」と解釈している。Webでは原画像を拡大して目盛りを確認できることを必須とし、読み取れた目盛範囲・1目盛りの値も表示する。具体的な表示方法は第12節で定義する。

以下は実装を始めやすくするための提案であり、ユーザーが確定した条件とは区別する。

- 初期入力はJPEG・PNGの静止画、1回の処理につき対象計器1個。
- 初期版では計器領域（ROI）の手動指定を許可する。単位・目盛・針先も含めて指定する。
- まず、1つの値と単位の組を読む。二重目盛・複数針・複数表示で対象を特定できない場合は要確認にする。
- 計器の自動検出、動画、撮影機器の制御は、読取と補正の効果を確認した後で追加する。
- 通常の写真・透視投影画像を初期入力とする。X5の全天球画像を直接扱う場合は、投影・座標変換を別途設計する。
- 読取VLMは交換可能にする。特定モデルの名称・料金・API仕様を処理本体へ埋め込まない。

## 2. 目的とエージェントの役割

目的は、画像に基づく値と単位の読取性能を改善し、結果を計器画像・目盛りと照合してWebで確認できるようにすること。計器別に履歴を保存して前日比較を行い、同じ結果をCSV・Excelへ出力できるようにする。

このシステムのエージェントは、VLMが画像・画質指標・試行履歴を確認し、用意された補正レシピから次の処理を選択するものとする。実行と制限の管理はPythonが行う。新規モデルの学習は初期版の前提にしない。

| 部品 | 担当すること |
|---|---|
| 画質解析 | 画像サイズ、輝度分布、明るさのむらの参考指標を計算 |
| Reader | 画像から計器種別、値、単位、目盛情報、観察できる根拠を抽出 |
| Planner | 未試行の補正レシピ、終了、再撮影推奨を選択 |
| Executor | 指定された画像処理を、検証済みパラメータで実行 |
| Validator | 出力形式、欠損、読取結果の矛盾、予算上限を確認 |
| Recorder | 元画像への参照、候補画像、結果、処理履歴を保存 |
| Repository | 計器、撮影ごとの観測、読取試行、人の確認履歴を永続保存 |
| ComparisonService | 同じ計器の前日確定値を選び、差と増減率を計算 |
| ExportService | Webと同じ検索条件・比較ルールでCSV/.xlsxを作成 |

ReaderとPlannerは論理的な役割であり、同じVLMを別の呼び出しで使ってよい。複数の独立したエージェントや専用フレームワークは初期版に必須ではない。[S1]

## 3. 画像補正の方針

### 3.1 小さく写る計器への対応

1. EXIFによる向きを適用した元画像から、元の解像度のままROIを切り出す。
2. 単位や目盛が欠けていないことを確認する。
3. まず未補正ROIを読む。
4. 必要に応じて補間拡大を試す。

全体画像を縮小する前に切り出すことで、計器に残っている画素を活かす。補間拡大によって失われた文字・針の情報が復元されるとは扱わない。API側の画像処理解像度もモデルごとに確認・記録する。[S2]

### 3.2 暗さ・明るさのむらへの対応

明るさ調整とCLAHEを候補にする。CLAHEは局所的なコントラスト調整として利用する。[S3] 明るさ指標の改善だけで、その候補を採用しない。

| レシピID | 固定された処理 | 主に試す条件 |
|---|---|---|
| resize_2x | 縦横2倍へ補間拡大 | 表示が小さく、元画像に細部が残る場合 |
| gamma_mild | 輝度チャンネルのガンマ補正 | 全体的に暗い場合 |
| clahe_mild | 輝度チャンネルのCLAHE | 局所的な明暗差・コントラスト不足 |
| gamma_clahe | ガンマ補正 → CLAHE | 暗さと明るさのむらが併存 |
| resize_gamma | ガンマ補正 → 2倍拡大 | 小さく暗い場合 |
| resize_clahe | CLAHE → 2倍拡大 | 小ささと明るさのむらが併存 |
| resize_gamma_clahe | ガンマ補正 → CLAHE → 2倍拡大 | 複合した劣化 |

未補正ROIは常に比較対象として残す。レシピの追加とパラメータ調整は開発用データで行う。

提案する初期値：

- ガンマ補正は、0〜1に正規化した輝度について「出力 = 入力の0.75乗」と定義する。逆数を使う実装と混同しない。
- CLAHEはclipLimit=2.0、tileGridSize=(8,8)を出発点にする。
- 小さなROIに対して過度に細かいタイルを使わないよう、タイル数の調整条件を実装する。
- 初期版はノイズ低減、シャープ化、射影補正を追加しない。効果の切り分けを優先する。
- これらの値は検証前の初期値であり、最適値・精度保証ではない。

### 3.3 データを変えすぎないためのルール

- 元画像は上書きしない。全候補を同じ未補正ROIから独立して生成する。
- 補正候補はPNGで保存し、JPEG再圧縮を繰り返さない。
- 拡大縮小は縦横比を維持する。
- 生成型超解像・画像生成による補完は初期版のレシピに含めない。導入時は別条件で評価する。生成型超解像には、入力と一致しない細部を生む問題がある。[S4]
- 単位・桁・小数点・符号・針を画像から判断できない場合、計器の一般的な仕様や期待値で補わない。

## 4. 入力・出力の契約

### 4.1 入力

| フィールド | 型・意味 |
|---|---|
| image_path | ローカルのJPEG・PNGへのパス |
| roi | [x1,y1,x2,y2] またはnull。EXIF向き補正後の元画像の画素座標 |
| target_type | analog / digital / auto。初期値auto |
| meter_id | 同一の物理計器・測定箇所を識別する固定ID。Web履歴では必須。単発CLIでは省略可だが前日比較をしない |
| observation_id | 撮影ごとの観測ID。未指定時に発行し、同じ観測の再読取では維持する |
| captured_at | 撮影・測定日時。タイムゾーン付きISO 8601文字列、またはnull |
| timestamp_source | user / exif / unknown。撮影日時の根拠 |
| acceptance_policy | 許容誤差・採用基準の設定。未設定なら自動採用しない |

ROIは左上を原点とし、x2・y2を含まない区間とする。整数座標について
「0 <= x1 < x2 <= 幅」「0 <= y1 < y2 <= 高さ」を検証する。
範囲外のROIを黙って切り詰めない。ROIがnullなら画像全体を対象とし、計器が小さい場合はROI指定を促す。

### 4.2 Reader出力

| フィールド | 型・意味 |
|---|---|
| meter_type | analog / digital / unknown |
| value | 有限のnumber、またはnull |
| raw_value_text | 観察した数字表記。例："0.40"。不明ならnull |
| unit | 画像から読める単位。正規化後の文字列、またはnull |
| raw_unit_text | 画像上の表記、またはnull |
| value_status | readable / uncertain / unreadable |
| unit_status | readable / uncertain / unreadable / not_present |
| value_evidence | 数字・小数点・符号、針と目盛の位置関係など、短い観察結果 |
| unit_evidence | 単位の位置・表記に関する短い観察結果 |
| issue_codes | small_text、dark、uneven_light、ambiguous_scaleなど |
| scale | 目盛り情報。min_value、max_value、minor_division、unit、status、sourceを持つオブジェクト |

readableなのに該当値がnull、といった矛盾は形式検証で検出する。uncertainの推定候補は履歴に残せるが、採用値と混同しない。欠損値を0に変換しない。

scaleの数値は不明ならnull。statusはreadable / partial / unreadable / not_applicable、sourceはimage / manual / registry / noneとする。デジタル計器で物理的な目盛りがない場合はnot_applicable。非線形目盛りや目盛間隔が不明な場合、minor_divisionを計算で補わない。登録済み仕様の表示は画像からの抽出と区別する。目盛情報の欠損だけで、読めている値・単位を欠損へ変えない。

Readerが返せるscale.sourceはimageまたはnoneに限定する。manualとregistryは人の確認処理・登録情報の取得処理が設定し、VLMに登録情報を作らせない。

単位の表記ゆれは明示的な変換表だけで扱う。PaとMPaのように倍率の異なる単位は、単位文字列だけを置換しない。換算を行う場合は値と単位を組にし、元表記も残す。

JSON Schema等による構造化出力が使えるAPIを優先する。[S5] 形式の正しさと、読取内容の正しさは別に検証する。

### 4.3 Planner出力

- action：apply / stop / recommend_recapture
- recipe_id：applyの場合のみ、3.2の登録済みID
- reason：選択理由を短く記録
- reason_codes：判断根拠を列挙

任意のコード・コマンド・関数名を実行対象にしない。Python側がIDを登録済み関数へ対応付ける。未登録ID、再試行済みID、形式不正の指定は実行しない。


statusは次の意味で使う。

| 状態 | 意味 |
|---|---|
| success | 値・単位が読み取れ、検証済みの採用基準を満たした |
| needs_review | 一部不明、結果の矛盾、未検証の採用基準、未確定候補を残して上限到達など |
| unreadable | 処理は実行できたが、使用可能な値・単位を得られなかった |
| error | 入力破損やAPI障害等で、有効な読取観察を得られなかった |

部分的に読めた場合はその項目を残してneeds_reviewにする。API障害を「画像が読めない」と誤分類しない。

## 5. 処理の流れと予算

1. 入力検証、EXIF向き補正、ROI切り出し、画質指標の記録。
2. 未補正ROIをReaderで読む。
3. 明瞭で採用基準を満たすなら終了候補にする。初期の基準未検証時はneeds_reviewとする。
4. 補正が必要なら、Plannerへ元ROI、画質指標、試行済みレシピ、読取状態を渡す。
5. Plannerの指定をPythonが検証し、元ROIから候補画像を作る。
6. 候補画像をReaderで読む。ここでは先行候補の数値を提示せず、同じ読取プロンプトで抽出する。
7. Validatorが各結果を比較する。追加処理の余地があれば4へ戻る。
8. 補正候補を採用したい場合、残予算があれば最終比較を1回行う。元ROIと候補を見て、支持できる候補ID、読取可否、矛盾だけを確認し、新しい数値を作らせない。
9. 採用基準・上限に基づき読取状態を確定し、画像と履歴を保存する。
10. Web連携時は観測IDと読取実行IDに関連付けてDBへ保存し、確認状態に応じて前日比較を計算する。Web・出力ファイルへ同じ結果を提供する。

過去の値・前日の値は、今回の値を推定するためにReaderやPlannerへ渡さない。前日比較は読取の後段で行い、比較の都合で画像から読んだ値を書き換えない。

Plannerには履歴を渡すが、Readerは候補ごとに独立した読取リクエストにする。同一モデルの複数回読取は、独立した正しさの証明にはならない。

| 制限 | 提案する初期値 |
|---|---|
| 補正候補数 | 最大2案。未補正ROIは別枠 |
| 通常の呼出構成 | 初回Reader 1回＋Planner/Reader各最大2回＋任意の最終比較1回 |
| 総API呼出数 | 最大6回。通信再試行・形式修正も同じ上限に含める |
| 1画像の総処理期限 | 120秒を開発時の初期値とし、実測で見直す |
| 1回のAPIタイムアウト | 最大30秒かつ残り総期限以内 |
| 通信再試行 | 1回まで。総回数・総期限が優先 |
| 料金 | 使用量を記録。金額上限はモデル・予算決定後に設定 |

停止判定はAPIを呼ぶ前と画像処理を実行する前に行う。再試行で上限を使った場合は、実施できなかった段階も履歴へ残す。最終比較が必要な採用条件なのに比較できなかった場合はsuccessにしない。

429等は再試行可能な通信状態として扱う。待機指示と残期限が両立しなければ終了する。JSON不正の修正依頼や無効なPlanner出力の再取得も予算外で実行しない。

## 6. 画質指標と結果の採用

画質指標は、ROIの幅・高さ、輝度p5/p50/p95、p95-p5、暗い画素や飽和付近の画素の割合、4×4分割した領域の輝度差などを候補とする。

これらは補正選択の参考情報であり、読取成功確率として表示しない。暗い目盛そのものを劣化と誤判定する場合もあるため、閾値は開発用データで調整する。

採用についてのルール：

- AIが出力する確信度だけでsuccessにしない。
- 値・単位の欠損、JSONの矛盾、目盛選択の不明確さを確認する。
- デジタル計器は小数点・符号を含めて比較する。数値比較には十進表現を使い、raw_value_textも保存する。
- アナログ計器は、事前に設定した許容差と単位で比較する。許容差未設定なら、食い違う読取結果を自動的に同一とみなさない。
- 読めたとされた元ROIと候補で結果が食い違う場合、多数決や最高確信度だけで決めずneeds_reviewにする。
- 元ROIが読取不能で候補だけが読める場合も、自動的に正解とは扱わない。最終比較と検証済み採用基準を通す。
- 単位が不明な場合に、「圧力計だからMPa」などと補わない。
- 校正用データで採用基準を検証するまではauto_accept=falseを既定にする。抽出値は画面・結果ファイルに表示できる。

## 7. 評価計画

### 7.1 正解データ

最初はアナログ・デジタルそれぞれ10〜20枚程度で処理の接続を確認し、その後、性能評価用の枚数と種類を増やす。少数枚の動作確認を精度保証に使わない。

- 正解は、同じ状態を捉えた明瞭な画像や計器記録を基に人が付ける。
- 撮影の間に値が変わる計器では、別時刻の写真を同じ正解として使わない。
- 明瞭な画像から、縮小・暗化・明るさのむらを付けたデータを作り、劣化強度ごとの比較を行う。
- 実環境の劣化画像も別に集める。人工的な暗化のみで実環境への有効性を結論付けない。
- 同じ元画像の加工版・同じ撮影連写は、開発用と最終評価用に分けない。
- 未知の計器への性能を見たい場合は、計器個体単位でも分割する。
- 正解ラベルは評価処理だけで使用し、Plannerや補正選択へ渡さない。

### 7.2 比較条件

| 条件 | 内容 | 比較の目的 |
|---|---|---|
| A | 全体の元画像をそのまま読む | 現状の基準 |
| B | 未補正ROIを読む | 切り出し自体の効果 |
| C | 同じROIへ固定補正を適用して読む | 通常の前処理の効果 |
| D | 同じROIでエージェントが補正を選択して読む | 適応的な選択を加えた効果 |

B〜Dは同じROIを使う。Cの固定補正は開発用データで選び、最終評価前に固定する。Readerのモデル、読取プロンプト、画像入力設定、正解判定条件を揃える。

Dは複数回読むため、選択の効果を詳しく調べる場合は「同じ試行予算で、ルールが補正を選ぶ条件」も追加する。精度だけでなく呼出数・処理時間を併記する。

### 7.3 指標

共通の評価対象N枚について、棄権・エラーも含めて集計する。

- 値の正解率：値が正しい画像数 / N。
- 単位の正解率：単位が正しい画像数 / N。
- 総合正解率：値と単位が両方正しい画像数 / N。
- 自動採用率：successの画像数 / N。
- 自動採用結果の誤り率：値または単位が誤っているsuccess数 / success数。successが0なら未定義と表示する。
- 読取不能率、要確認率、技術エラー率。
- 処理時間、API呼出数、使用量。料金情報がなければ金額を推測で埋めない。

needs_reviewに残した抽出候補の正解率と、自動採用した結果の正解率は分けて報告する。

デジタル計器は表示値の小数点・符号を含めた一致を基本とし、末尾0はraw_value_textで確認できるようにする。アナログ計器は正解区間または許容誤差を事前定義する。相対誤差は正解0で定義できないため、絶対誤差も用いる。

目標精度・許容誤採用率・実用上の待ち時間は、基準性能と用途を確認してから数値化する。未検証の90%・95%などを合格値として固定しない。

## 8. 実装する構成

読取処理はPython＋OpenCV＋VLM APIクライアントを基本案とする。JSONの型・制約を検証するため、Pydantic等のバリデーションを用いる。Web部分はPythonのAPIサーバー、SQLiteによる履歴保存、ブラウザ用UIを追加する構成を提案する。UIのフレームワークは実装環境・既存コードに合わせて決定する。CSVはPythonのcsv、.xlsxはopenpyxl等で出力する。[S6][S7] ライブラリの版は実装時に確認して固定する。

| モジュール | 責務 |
|---|---|
| schemas.py | 入力、Reader出力、Planner出力、最終結果の型 |
| image_io.py | デコード、EXIF向き補正、ROIと元画像の管理 |
| quality.py | 参考画質指標の計算 |
| tools.py | 登録済み補正レシピ。元画像は変更しない |
| reader.py | VLMへの独立した読取リクエスト |
| planner.py | 次のレシピ・停止の選択 |
| provider.py | API差分、タイムアウト、使用量の取得 |
| validator.py | 結果の整合性・採用ポリシーの確認 |
| agent.py | 状態、予算、停止条件、呼出順序の管理 |
| evaluate.py | 正解付きデータとの比較 |
| cli.py | 単一画像とフォルダ単位の実行 |
| repository.py | 計器・観測・試行・確認履歴と画像参照の保存 |
| comparison.py | 前日参照の選択、単位整合、差と増減率の計算 |
| export.py | 共通の結果一覧からCSV/.xlsxを生成 |
| web_api.py | 画像登録、処理状況、一覧・詳細、確認操作、出力を提供 |
| web/ | 計器一覧、観測詳細、画像・目盛り確認、履歴と出力の画面 |

Web画面は今回の必須機能として、第12節の一覧・詳細・確認操作を実装する。画面には元画像・元ROI・補正画像、目盛情報、読取候補と採用値、単位、前日比較、判定状態、実行した処理を表示する。人が確認・訂正した値は、モデルの予測値を上書きせず別に保存する。Web画面、CLI、出力処理が同じ読取・比較ロジックを呼ぶ構成にする。

読取の実行はWebの画面表示要求から分離し、処理状況を取得できるようにする。ジョブ状態（queued/running/completed/failed）と読取状態（success/needs_review/unreadable/error）を区別する。例えば読取不能という結果を正常に保存できたジョブはcompletedとする。APIキーはサーバー側で扱う。初期版はローカルまたは限定した利用環境を想定し、公開範囲と利用人数はWeb実装前に確定する。

保存する履歴には、入力ハッシュ、ROI座標、処理レシピ、パラメータ、候補ごとの読取結果、モデルID、プロンプト版、画像入力設定、実行時間、使用量、停止理由を含める。APIキーや認証ヘッダーは保存しない。

## 12. Webでの結果確認と履歴保存

### 12.1 一覧画面

- 計器ごとの最新観測を、画像サムネイル、計器ID・名称、撮影日時、読取値・単位、目盛情報、判定・確認状態、前日差・増減率とともに表示する。
- 最新の観測が読取不能でも隠さない。過去の確定値を最新値として見せず、必要なら「直近の確定値」として撮影日時を添えて別表示する。
- 計器、撮影期間、日本時間の日付、読取状態、確認状態で絞り込める。
- 「CSV出力」「Excel出力」ボタンから、現在の検索条件に一致する全件を出力する。画面の1ページ分だけにしない。
- 計器別の履歴一覧から、過去の画像と読取結果へ戻れる。

### 12.2 詳細画面と目盛りの確認

- 全体の元画像、未補正ROI、採用候補の補正画像を切り替え・並列表示でき、拡大と移動で目盛り・数字・単位を確認できる。
- 読取値・単位、目盛りの最小値・最大値・1目盛りの値、抽出根拠、使った補正、処理状態を表示する。
- 元画像の目盛りそのものと、抽出された目盛情報の両方を確認できるようにする。
- 目盛情報が不明なら「不明」、デジタル計器等で該当しなければ「対象外」と表示する。均等でない目盛りから一定の1目盛り値を作らない。
- 二重目盛は対象とした単位・目盛りを明示する。どちらか選べなければ要確認とする。
- 登録情報から補助表示する目盛範囲は「登録値」と表示し、画像から読んだ情報と混同しない。
- 前日参照の値・単位・撮影日時と、参照した観測の詳細へのリンクを表示する。
- 人が「確認済みにする」「値・単位・目盛情報を訂正する」「採用しない」を選べる。元のモデル出力と訂正内容・理由・時刻を残す。
- review_statusはunreviewed / confirmed / rejectedとする。訂正して確認した場合もconfirmedとし、訂正の有無と内容を別に記録する。read_statusは元の読取状態として保持する。
- 候補値と採用値を区別し、未確認の値から計算した前日比を確定結果として表示しない。

### 12.3 永続データの区分

| データ | 主な項目 |
|---|---|
| meters | 固定meter_id、表示名、計器種別、設置箇所、登録単位・目盛範囲、系列の版 |
| observations | observation_id、meter_id、captured_at、日時の根拠・タイムゾーン、元画像参照、ハッシュ、ROI、選択中の読取実行ID |
| read_runs | 観測IDに属する実行ID、候補と処理履歴、値・単位・目盛情報、読取状態、モデル・使用量・処理時刻 |
| reviews | 対象の観測・読取実行ID、確認・訂正・却下、訂正値、理由、確認時刻。履歴を追記して保存 |
| assets | 元画像・ROI・補正画像のIDと保存先の対応 |

- DBと画像ファイルは再起動後も残る。ブラウザの一時保存だけを履歴の保存先にしない。
- 観測IDは1回の撮影・測定を表す。同じ画像の補正候補や再読取は別の観測として日次集計に追加しない。
- 再読取は新しいread_runとして保存する。選択実行が変わった場合、古い実行への確認済み状態を無条件に引き継がない。
- アップロード要求の再送で同じ観測が二重登録されないよう、観測IDまたは冪等キーを用いる。
- 同じ物理計器の同じ測定箇所へ、日をまたいで同じmeter_idを使う。名称の一致だけで同一計器と判定しない。
- 計器交換や測定対象・設定の変更で比較の意味が変わる場合、系列の版を変えて過去との自動比較を止める。
- 撮影日時と処理日時を分ける。撮影日時が不明でも結果保存は可能だが、前日比較を行わない。
- 日時はタイムゾーン付きで受け取り、保存はUTC、日付判定・表示はAsia/Tokyoを初期設定とする。タイムゾーンなしEXIF日時は、取込設定を明示して解釈する。
- Webへは画像ID・画像取得用URLを返す。サーバーの絶対ファイルパスを表示用URLに流用しない。

## 13. 前日比較の定義

以下を初期の計算ルール案とする。計算はPython等の通常の数値処理で行い、VLMに計算させない。

### 13.1 比較対象

- 対象は同じmeter_id・同じ系列の版に属する観測。
- 「前日」は対象観測の撮影日時から決まる日本時間の日付の1日前。直前24時間や単なる直前の観測とは区別する。
- 当日・前日とも、比較に使える値は「検証済み自動採用基準を満たす値」または「対象の読取実行について人が確認・訂正した値」。
- 前日に複数の比較可能な観測がある場合は、撮影日時が最も新しいものを代表値とする。同時刻ならobservation_idの順など固定の規則で選ぶ。
- 前日が未確認の観測だけなら「前日確定値なし」。前々日等へ自動でさかのぼらない。
- 一覧の各観測はその観測の撮影日を基準に比較する。計器ごとの最新表示でも、実際に表示中の観測の撮影日時を基準とする。
- 単位が異なる場合は、明示的な換算表がある同じ測定量に限り共通単位へ変換する。換算不能・単位不明なら比較しない。
- 履歴を絞り込んだ期間の外に前日値があっても、参照可能なら比較に使う。画面の検索範囲で前日選択を変えない。

### 13.2 計算と表示

比較単位に揃えた今回値をcurrent、前日値をpreviousとする。

- 前日差：delta_value = current - previous。計器と同じ比較単位を付ける。
- 前日増減率：delta_percent = (current - previous) / previous × 100。前日値が正の場合に計算する。
- Webの「前日比」欄は「前日差」と「前日増減率」を区別して表示する。「110%」と「+10%」を混同しない。
- 例：前日0.40 MPa、今回0.44 MPaなら、前日差+0.04 MPa、増減率+10.0%。
- 前日値が0の場合、前日差は表示し、増減率は「算出不可（前日値0）」。
- 負の前日値では百分率の解釈を固定しないため、初期版は前日差のみ表示し、増減率は「算出対象外（前日値が負）」。
- 前日欠損、日時不明、現在値未確定、単位不整合、系列変更では該当する比較値をnullとし、理由を表示する。0差・0%で埋めない。
- 数値の計算には十進数を用い、表示時にだけ丸める。表示桁数は計器の分解能または設定に合わせる。

### 13.3 記録と再計算

comparisonには参照観測ID、参照した読取・確認の版、前日値・単位・撮影日時、delta_value、delta_percent、比較状態、増減率の状態を持たせる。

- comparison_status：ok / no_reference / current_unconfirmed / previous_unconfirmed / timestamp_unknown / unit_incompatible / series_changed。
- percent_status：ok / zero_baseline / negative_baseline / unavailable。
- 前日0・負値でも前日差が計算できる場合、comparison_statusはok、percent_statusで百分率を出せない理由を表す。
- 人が値を訂正したら、影響する当日・翌日の表示と以降の出力を再計算する。元のモデル出力や訂正履歴は消さない。
- Web・CSV・Excelは同じ比較サービスを利用する。画面と出力で別の計算式を持たせない。

## 14. CSV・Excel出力

### 14.1 対象と列

- ユーザーが指定した計器・期間・状態・確認状態に一致する観測を出力する。既定は候補・エラーも含む検索結果全件。
- 1行は1観測とし、選択中の読取実行と確認状態を出力する。全補正候補を独立した測定行にしない。
- モデルの予測値と、人の確認を含めた採用値を別列にする。未確定の採用値は空欄にする。
- 前日参照は出力時点の同じデータスナップショットから計算する。処理中の観測は読取結果の表に混ぜず、ジョブ画面で確認できるようにする。
- 検索応答と出力へdata_revisionを付ける。画面表示後にデータが変わった場合は一覧を再取得してから出力し、古い表示と新しい出力を同じ結果として扱わない。

必須の列群：

| 列群 | フィールド |
|---|---|
| 観測情報 | observation_id、meter_id、meter_name、captured_at_jst、processed_at_jst、meter_type |
| 読取結果 | value、unit、raw_value_text、value_status、unit_status、read_status、review_status |
| 採用値 | effective_value、effective_unit、effective_source（auto / human / none） |
| 目盛り | scale_min、scale_max、scale_step、scale_unit、scale_status、scale_source |
| 前日参照 | reference_observation_id、previous_captured_at_jst、previous_value、previous_unit |
| 比較値 | delta_value、comparison_unit、delta_percent、comparison_status、percent_status |
| 画像・詳細 | image_id、detail_url（取得できる場合） |

### 14.2 CSV

- ヘッダー付きUTF-8 BOMを初期形式とし、拡張子は.csv。
- csvモジュール等でカンマ・引用符・改行を正しくエスケープする。[S6]
- 日時は「2026-10-27T10:00:00+09:00」のようにタイムゾーンを明示する。
- 不明値・計算不能値は空欄にし、状態・理由の列で区別する。
- delta_percentは百分率の数値を格納する。+10.0%なら10.0を出力し、列名・説明で%単位を明示する。
- 画像はimage_idと詳細画面の参照を出力する。CSVに画像バイナリを埋め込まない。

### 14.3 Excel

- .xlsxとして、openpyxl等で出力する。[S7]
- 「Readings」：CSVと同じ観測と列。「Meters」：対象計器の登録情報。「ExportInfo」：出力日時、フィルター、タイムゾーン、比較ルール、仕様版。
- 見出し、フィルター、見出し行の固定、列幅、数値書式を設定し、数値・単位・状態を確認しやすくする。
- 値・前日差は数値セル、欠損は空セル。IDと元の数字表記は文字列として保持する。
- delta_percentはCSVと同じ百分率値10.0を保存し、末尾の%を文字として表示する書式を使う。通常の百分率書式でさらに100倍した表示にしない。
- 手入力文字列・AI出力文字列は文字列として出力し、セルの式として実行させない。比較値は計算済みの数値を出力する。
- 初期版は画像ID・詳細リンクを含める。Excelへの画像埋め込みは、この版の必須要件に含めない。

### 14.4 出力の検証条件

- Web検索結果の全ページと、CSV/Excelの対象件数・観測IDが一致する。
- 同じ観測について、採用値・単位・前日参照・差・増減率・状態が一致する。
- 前日0、負値、欠損、日付境界、単位換算、未確認値、人の訂正を扱える。
- Excelで+10.0%が+1000%と表示されない。0と空欄を区別する。
- CSVで日本語、カンマ、引用符、改行を含む名称・理由を往復できる。
- 出力処理はVLMを再実行せず、保存済み結果から作る。
