# 20枚のROI準備・評価・データ出力

作業ブランチは `feature/image-agent-web`。
1枚の結果から性能を結論付けず、ユーザーの公開開発画像20枚で同じ条件のデータを取るための追加実装。
Reader・Plannerの読取精度の調整、正解に合わせたプロンプトやレシピの変更は行わない。
実APIの実行は従来どおりローカルで行い、クラウドでは通信モックのみで検証した。

## 準備

`batch_prepare.py` は取得スクリプトの元inputs.jsonlか既存の入力専用ObservationInput形式を読む。
元の質問文を保持し、provenanceがあればrevision・seed等を保持する。正解ファイルは読み込まない。
全画像・ID重複・件数（CLI既定20）・手動上書きの形式を通信前に検証する。
元画像・質問・入力設定のfingerprintをworkspaceへ保存する。

ROIだけを既存のROILocatorで提案し、画像・応答・確認用の枠と20枚一覧を保存する。
数値は読まない。ROIがlocatedなら同じ提案を検証して再利用し、無条件に再取得しない。
通信エラーとpendingは再開でき、曖昧／不在の再提案は--retry-unresolvedで明示する。
手動上書きはquestion_idから元画像xyxy範囲へのJSONで受け取り、元の提案・過去の応答を保持する。
画像・質問が変われば既存workspaceを拒否する。

## 比較と欠損

`benchmark.py --prepared-batch` は全20ケースを取り込む。
確定した座標をB〜Dへ同じように渡し、比較中にROI APIを再実行しない。
未確定ROIではAだけを全体画像で読み、B〜Dを要確認／技術エラーとして未実施にする。
全体画像への代替やケース除外はしない。全条件に同じ20件を宣言し、評価の分母を保つ。
ROIが曖昧／不在ならneeds_review、ROI準備の通信障害等ならerrorとして記録する。

準備状態のスナップショットとハッシュ・準備用通信回数を実験へ記録する。
ROI取得はA〜Dの前段なので通信回数を別枠で示す。B〜Dの元ROIは同じままである。
各runの6通信・120秒、同一CLIでの料金枠を維持する。別プロセス間の費用予約は引き継がない。

## 再開と出力

benchmarkは開始時にmanifestの保存先をstderrへ表示し、各条件の進捗を出す。
--resumeで同じ実験を再開すると、完了済み結果のハッシュを確認してスキップする。
完了済み技術エラーの再取得はしない。入力・質問・ROI・固定レシピ・Reader設定・DB保存先は一致を要求する。
生成済みrunが記録済みならAPIを呼び直さず保存処理を再開する。
通信中に中断され完了有無が不明なら未完了のrunだけ再実行し、過去分の使用量等は推測しない。
そのケースの通信回数・トークン・費用合計をnullにして、不明な送信を0として集計しない。
中断前のrunファイルがあっても上書きしない。

evaluationは従来のJSONに加えてsummary.csvとcases.csvを同じ一意ディレクトリへ保存する。
全体・元ラベルのimage_type別で同じ指標を集計し、casesは80行になる。
値＋単位の全体正解率、候補を出せた場合の正解率、棄権率、ROI未実施数を区別する。
未実施ROIでもN=20に含め、理由を明示する。区間・単位群の対応を保持し、正解を入力工程へ戻さない。
nullはCSVでは空欄、JSONではnull。文字列の式解釈を避け、数値欄は数値のまま出す。
このCSVは評価データ用であり、段階7の運用履歴・前日比較のCSV／Excel出力とは別である。

## 検証

既存204件＋一括処理15件＝219件の自動テストで、入力変換、件数、提案の再利用、
曖昧状態の再取得制御、上書き、認証エラーでの停止、分母維持、再開・設定変更拒否・
中断後の使用量不明、カテゴリー集計、CSVの構造・文字列処理を確認した。

実画像20枚では、ROI用に架空の矩形15件・架空の曖昧状態5件を返す模擬HTTPを使用した。
これは実物の計器検出結果ではなく、ROI推定の精度を評価していない。
ROI準備20模擬送信後、同じ準備コマンドの再開では追加通信0。
MockReaderで全80ケースを宣言し、65runを保存、ROI未確定15ケースを未実施として保持した。
全体N=20、5種類の計器別集計、summary.csv24行・cases.csv80行を確認した。
完了した実験の再開でReader追加実行0。元画像と入力・正解・provenanceは不変だった。
実API0、実ネットワーク0、数値の正解率は未評価でnullのままである。
